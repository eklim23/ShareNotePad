# 오류 시나리오 처리표

## 목표

오류가 나도 프로그램은 죽지 않아야 한다.

사용자 문서는 유지되어야 하며, 가능한 경우 전체 동기화로 회복한다.

## 연결 오류

| 상황 | 감지 | 처리 | 사용자 표시 |
| --- | --- | --- | --- |
| 호스트 IP 틀림 | connect timeout | 연결 중단 | 상대 노트북에 연결할 수 없습니다. |
| 포트 닫힘 | connect 실패 | 연결 중단 | 연결 주소 또는 포트를 확인하세요. |
| 방화벽 차단 | timeout | 안내 표시 | Windows 방화벽에서 막혔을 수 있습니다. |
| 상대 종료 | recv 0 bytes | 재연결 상태 | 연결이 끊겼습니다. |
| PING 무응답 | 15초 timeout | 재연결 시작 | 재연결 중... |

## 방 입장 오류

| 상황 | 서버 응답 | 처리 | 사용자 표시 |
| --- | --- | --- | --- |
| 초대 코드 틀림 | `JOIN_FAIL invalid_code` | 시작/입장 화면 유지 | 초대 코드가 맞지 않습니다. |
| 방이 가득 참 | `JOIN_FAIL room_full` | 입장 중단 | 이 방은 이미 사용 중입니다. |
| 코드 만료 | `JOIN_FAIL expired_code` | 입장 중단 | 초대 코드가 만료되었습니다. |
| 버전 불일치 | `JOIN_FAIL protocol_mismatch` | 입장 중단 | ShareNotepad 버전이 다릅니다. |

## 동기화 오류

| 상황 | 감지 | 처리 |
| --- | --- | --- |
| revision 건너뜀 | `APPLY.rev != current + 1` | `SYNC_REQUEST` |
| position 범위 오류 | 서버 검증 실패 | `ERROR`, 필요 시 `SYNC_REQUEST` |
| 메시지 파싱 실패 | JSON 오류 | 메시지 무시, 카운트 증가 |
| 문서 크기 초과 | 적용 전 검사 | 적용 거절 |
| 원격 적용 중 EN_CHANGE 발생 | `remoteApplying` | 이벤트 무시 |

## 저장 오류

| 상황 | 처리 | 사용자 표시 |
| --- | --- | --- |
| 저장 폴더 생성 실패 | 재시도 후 로그 | 자동 저장 실패 |
| current.tmp 쓰기 실패 | current.txt 보존 | 자동 저장 실패 |
| 파일 교체 실패 | tmp 보관 | 자동 저장 실패 |
| 백업 생성 실패 | current 저장은 계속 | 백업 실패, 작업은 계속됩니다. |

## 비정상 종료 복구

| 상황 | 처리 |
| --- | --- |
| `current.txt` 정상 | 로드 |
| `current.tmp` 남음 | 백업으로 보관 |
| 둘 다 깨짐 | 가장 최근 backup 로드 후보 |
| session.log만 있음 | MVP에서는 자동 재구성하지 않음 |

## 충돌 상황

MVP는 CRDT/OT를 사용하지 않는다.

정책:

- 서버가 먼저 받은 순서대로 revision을 부여한다.
- 클라이언트는 서버 revision 순서대로만 반영한다.
- 불일치가 감지되면 전체 문서 동기화로 복구한다.

동시 입력 결과가 사용자의 직관과 조금 다를 수 있으나 MVP에서는 허용한다.

## 프로그램이 죽으면 안 되는 영역

다음 오류는 예외가 발생해도 프로세스를 종료하지 않는다.

- 잘못된 네트워크 메시지
- 연결 끊김
- 잘못된 초대 코드
- 동기화 revision 불일치
- 자동 저장 실패
- 백업 실패

프로세스 종료가 허용되는 경우:

- 사용자가 종료 버튼을 누름
- 치명적인 초기화 실패 후 UI 표시도 불가능함
