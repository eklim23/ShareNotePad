# MVP 범위 확정서

## 목표

ShareNotepad MVP는 같은 내부망에 있는 두 대의 Windows 노트북에서 하나의 텍스트 문서를 거의 즉시 공유 편집하는 초경량 프로그램이다.

사용자가 알아야 하는 개념은 세 가지로 제한한다.

1. 방 만들기
2. 방 들어가기
3. 같이 쓰기

## MVP 포함 기능

| 구분 | 기능 | 기준 |
| --- | --- | --- |
| 실행 | 빠른 실행 | 실행 후 1초 이내 메인 화면 표시 |
| 연결 | 방 만들기 | 로컬 미니 서버 시작, 초대 코드 생성 |
| 연결 | 방 들어가기 | 초대 코드만 입력하면 자동 탐색 후 접속 |
| 편집 | 텍스트 입력 | 일반 메모장처럼 입력, 삭제, 붙여넣기 |
| 동기화 | 실시간 반영 | INSERT/DELETE 이벤트를 상대방에 반영 |
| 저장 | 자동 저장 | 입력 후 1~3초 내 `current.txt` 저장 |
| 상태 | 연결 표시 | 연결됨, 끊김, 재연결 중 표시 |
| 복구 | 재접속 동기화 | 재연결 시 최신 문서 전체 동기화 |

## MVP 제외 기능

다음 기능은 MVP에 넣지 않는다.

- 계정 로그인
- 비밀번호 기반 사용자 관리
- 클라우드 저장소 연동
- 사용자가 직접 설정해야 하는 VPN/Tailscale/ZeroTier 의존
- 이미지 첨부
- 파일 첨부
- 마크다운 렌더링
- 다중 문서
- 3명 이상 동시 편집
- 복잡한 권한 관리
- 음성/영상 통신

## 로그인 정책

MVP에는 로그인 기능을 넣지 않는다.

이유:

- 계정 서버와 DB가 필요해져 구조가 무거워진다.
- 비밀번호, 토큰, 개인정보 처리 책임이 생긴다.
- "켜고 바로 같이 쓰기"라는 제품 경험과 충돌한다.

대신 MVP는 다음 방식으로 사용자를 구분한다.

- 로컬 `device_id`
- 선택 입력 가능한 `nickname`
- 방 생성 시 만들어지는 `session_code`
- 접속 성공 후 발급되는 `reconnect_token`

## 연결 UX 정책

사용자에게 IP, 포트, VPN, Tailscale, ZeroTier 같은 네트워크 설정을 요구하지 않는다.

기본 UX:

```text
방 만들기 -> 초대 코드 표시
방 들어가기 -> 초대 코드 입력 -> 자동 연결
```

IP/포트 직접 입력은 일반 사용자 화면의 기본 흐름이 아니라 고급/디버그 옵션으로만 둔다.

자동 연결 우선순위:

1. 같은 LAN에서 UDP discovery로 방 코드 탐색
2. 실패 시 ShareNotepad가 관리하는 rendezvous/relay 서버 조회
3. 그래도 실패하면 사용자에게 연결 실패를 안내

외부 rendezvous/relay 서버는 사용자에게 별도 설치나 네트워크 설정을 요구하지 않기 위한 제품 인프라다. 문서 내용 저장이나 계정 로그인과는 별개이며, MVP 내부망 구현 이후 별도 단계로 추가한다.

## 성공 기준

MVP는 아래 흐름이 안정적으로 동작하면 성공으로 본다.

1. 노트북 A에서 ShareNotepad 실행
2. 방 만들기
3. 노트북 B에서 ShareNotepad 실행
4. 방 들어가기
5. 초대 코드만 입력
6. A 입력이 B에 반영
7. B 입력이 A에 반영
8. 양쪽 모두 자동 저장
9. 연결 끊김 후 재접속 시 최신 문서 복구

## 우선순위

1. Win32 메모장 UI
2. 자동 저장
3. TCP 연결
4. 방 만들기/들어가기
5. LAN 자동 탐색
6. INSERT 동기화
7. DELETE 동기화
8. 전체 SYNC
9. 재연결
10. 보안 제한
11. 앱 관리 rendezvous/relay 서버
