# 세션 인증과 보안 설계서

## 목표

MVP는 로그인 없이 동작한다.

대신 방 코드와 세션 토큰으로 최소한의 접속 제한을 제공한다.

## 인증 모델

사용자 계정:

- 없음

MVP 식별자:

| 값 | 저장 위치 | 목적 |
| --- | --- | --- |
| `device_id` | `config.ini` | 로컬 장치 식별 |
| `nickname` | `config.ini` | UI 표시 이름 |
| `session_code` | 메모리 | 방 입장 코드 |
| `reconnect_token` | 메모리/옵션 저장 | 재접속 식별 |

## 초대 코드

MVP:

```text
482913
```

규칙:

- 6자리 숫자
- 암호학적으로 안전한 난수 사용
- 세션 생성 시마다 새로 생성
- 기본 유효 시간 10분

확장:

```text
482913-K7XQ2
```

## reconnect_token

입장 성공 시 서버가 발급한다.

규칙:

- 최소 128bit 랜덤
- 세션 종료 시 폐기
- 로그에 원문 기록 금지
- 재접속 시 같은 peer인지 확인하는 용도

## 메시지 검증

서버는 모든 메시지를 검증한다.

검증 항목:

- `type`이 허용된 값인가
- `session`이 현재 방 코드와 일치하는가
- `client`가 등록된 peer인가
- JSON 크기가 64KB 이하인가
- 문자열이 UTF-8로 유효한가
- `pos`가 문서 범위 안인가
- `len`이 문서 범위 안인가
- `text`가 32KB 이하인가
- 적용 후 문서가 5MB 이하인가

## 비정상 요청 처리

| 상황 | 처리 |
| --- | --- |
| 잘못된 JSON | 무시, 오류 카운트 증가 |
| 잘못된 session | JOIN 전이면 실패, JOIN 후면 종료 |
| 메시지 크기 초과 | 연결 종료 |
| position 오류 | ERROR 응답 후 SYNC 유도 |
| 잘못된 코드 5회 | 연결 종료 |

## 평문 통신

MVP 내부망 버전은 TCP 평문 통신을 사용한다.

주의:

- 같은 네트워크의 공격자에게 내용이 노출될 수 있다.
- 민감한 문서 공유 용도로 안내하지 않는다.

외부망 버전에서는 TLS가 필수다.

## 외부망 확장 보안

외부 릴레이 서버 추가 시 필수:

- TLS
- 세션 토큰
- 초대 코드 만료
- 초대 코드 1회성 처리
- 서버에 평문 문서 저장 금지 옵션
- 최소 로그 정책
- IP 제한 옵션

## 로그인 도입 기준

다음 조건 중 하나가 생기면 로그인 도입을 검토한다.

- 여러 장치에서 같은 문서를 이어서 열어야 한다.
- 외부망 중앙 릴레이 서버가 상시 운영된다.
- 문서 목록/히스토리를 클라우드에 저장한다.
- 팀 단위 권한 관리가 필요하다.

로그인을 도입한다면 우선순위는 다음과 같다.

1. 일회성 방 링크
2. 이메일 매직코드
3. Google/Microsoft OAuth
4. 직접 비밀번호 로그인

MVP에서는 직접 비밀번호 로그인을 구현하지 않는다.
