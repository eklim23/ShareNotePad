# 테스트 계획서

## 목표

ShareNotepad MVP의 핵심 위험은 세 가지다.

1. 편집 이벤트가 잘못 계산되는 문제
2. 네트워크 끊김/재연결 문제
3. 저장/복구 실패 문제

테스트는 이 세 영역을 우선한다.

## 단위 테스트

### 프로토콜

- 유효한 JSON 메시지 파싱
- 깨진 JSON 무시
- length frame 분리
- 2개 메시지가 한 번에 들어오는 경우
- 메시지가 여러 recv에 나뉘어 들어오는 경우
- 64KB 초과 메시지 거절

### 편집 diff

- 끝에 글자 추가
- 중간에 글자 추가
- 앞에 글자 추가
- 끝에서 삭제
- 중간 삭제
- 전체 선택 후 붙여넣기
- 한글 문자열 삽입
- 줄바꿈 포함 붙여넣기
- DELETE 후 INSERT가 동시에 필요한 변경

### 문서 operation 적용

- INSERT 정상 적용
- DELETE 정상 적용
- position 범위 초과 거절
- len 범위 초과 거절
- revision 순서 확인

### 저장

- `current.txt` 저장
- `current.tmp` 생성 후 교체
- UTF-8 한글 저장/로드
- 빈 문서 저장
- 1MB 문서 저장
- 저장 실패 시 기존 current 보존

## 통합 테스트

### 단일 PC

1. 프로세스 A 실행
2. 방 만들기
3. 프로세스 B 실행
4. `127.0.0.1:7777`로 접속
5. A 입력이 B에 반영
6. B 입력이 A에 반영

### 두 노트북

1. 같은 와이파이에 연결
2. 노트북 A 방 만들기
3. 노트북 B 방 들어가기
4. 초대 코드/주소 입력
5. 양방향 입력 확인

### 연결 끊김

- B 프로세스 종료
- A 상태바가 끊김으로 바뀌는지 확인
- B 재실행 후 재접속
- 최신 문서 동기화 확인

### 호스트 종료

- A 종료
- B가 연결 끊김을 감지하는지 확인
- B 문서가 로컬에 유지되는지 확인

## IME 테스트

한글 입력:

- `안녕하세요` 연속 입력
- 조합 중 상대 화면에 미완성 글자가 전송되지 않는지 확인
- 받침 있는 글자 입력
- 한영 전환
- 한글 붙여넣기
- 긴 문장 붙여넣기

예상:

- 조합 확정 후 상대에게 반영
- 중복 글자 없음
- 깨진 문자 없음

## 성능 테스트

| 테스트 | 기준 |
| --- | --- |
| 실행 시간 | 1초 이내 메인 화면 |
| 대기 상태 | CPU 1% 이하 |
| 빠른 입력 | 초당 100개 이벤트 처리 |
| 1MB 문서 | 열기/동기화 가능 |
| 5MB 문서 | 제한 내 동작 |
| 장시간 사용 | 10분 이상 메모리 급증 없음 |

## 수동 테스트 체크리스트

- 방 만들기 버튼 동작
- 초대 코드 생성
- 포트 표시
- 방 들어가기 성공
- 잘못된 코드 실패
- 연결됨 상태 표시
- 지연 시간 표시
- 자동 저장 완료 표시
- A -> B 입력 반영
- B -> A 입력 반영
- 삭제 반영
- 붙여넣기 반영
- 한글 입력 반영
- 연결 끊김 표시
- 재접속 후 전체 동기화
- 종료 후 `current.txt` 유지
